# Vichar AI — project notes

## Architecture
- Monorepo without workspaces: `apps/api` (Express + `node:sqlite`, port 4000) and `apps/web` (Next.js 14 App Router, port 3000). The web app proxies `/api/*` to the API via `next.config.mjs` rewrites. See `.freebuff/run.md` for how to run both.
- The API is the product: full auth (JWT access + hashed opaque refresh cookies), chat with SSE streaming, emotion detection, RAG, memory extraction, crisis safety, moods/journal/goals/sessions, GDPR export, audit log. The web app ships a marketing landing page plus app pages: `/login`, `/signup`, `/home` (companion picker + mood check-in), `/journal` (the calming journal sanctuary: home/write/read views), `/chat` (SSE streaming chat with emotion orb and crisis banner), and static `/crisis`, `/privacy`, `/terms`. Protected pages use `components/RequireAuth.tsx`.
- **Journal endpoints live at `/api/journal` and `/api/journal/:id` (GET/POST/DELETE), NOT `/api/moods/journal`** — the routes are defined inside `moods.routes.ts` but the router is mounted at `/api` (see the mount comment in `index.ts`). Calling `/moods/journal` 404s. The journal page (`apps/web/src/app/journal/page.tsx`) also autosaves a draft to `localStorage` key `vichar:journal:draft` (title/content/moods/gratitude) and restores it when opening the write view; mood picked in the write view is `moodKey`, extra moods go in `tags`. Ambient tone is driven by the picked mood or today's logged mood (anxious → breathing-card + teal-blue blobs, sad → dusty blue, joy → warm orange); the WebAudio rain ambience generates filtered white noise in code — no audio assets. The journal is re-themed to a warm cozy desk palette (beige-orange wall tones, teal accents, cream paper, amber `.btn-warm` buttons that override `.btn-primary` by source order) and uses Poppins for UI type plus the handwritten **Caveat** font (`--font-caveat`, in `layout.tsx`) for quotes/dates/whispers via the `.jrnl-hand` class. Journal preferences persist to localStorage: theme `vichar:journal:theme` ("auto" = mood-driven palette, or one of 10 named themes like desk/night/blossom), favorites `vichar:journal:favorites` (array of entry ids). A floating bottom nav (`.jrnl-nav`) with Home / Journal / ＋ sits on all journal views. The mood picker has 15 moods (keys: happy/calm/peaceful/loved/hopeful/motivated/empty/sad/hurt/lonely/tired/anxious/overwhelmed/angry/confused).
- The chat page keeps the accumulated streamed text in a ref (`pendingTextRef`) so the `onDone` closure sees the full reply; for a brand-new conversation it syncs messages from the server instead of also appending locally (appending both duplicates the assistant bubble).
- The journal is now gated by a client-side private diary vault. `GET/PUT /api/journal/vault` stores only the PBKDF2 parameters and AES-GCM-wrapped random diary key. The password never reaches the API. New journal entries send only `date` plus `encryptedPayload`; legacy plaintext entries migrate through `PUT /api/journal/:id` after a successful unlock. Drafts use the per-user `vichar:journal:draft:v3:<user-id>` key and are encrypted; the old shared v2 draft migrates after a successful decrypt. Do not reintroduce plaintext or cross-user draft storage. Draft encryption starts immediately and uses a revision guard so quick navigation and late promises cannot lose or revive a draft.
- `NotebookEditor.tsx` renders the open-diary spread and the saved-entry paper. Caveat is the default font; font, page colour, paper, ink, and decoration settings live at `vichar:notebook:prefs:v2` and an appearance snapshot is encrypted inside each v2 entry. `AmbientSoundMixer.tsx` procedurally generates rain, wind, birds, ocean, fireplace, and deep-focus ambience with Web Audio and needs no asset files. The vault has four local cover choices at `vichar:journal:cover:v1`.

## Non-obvious code facts
- The Next.js rewrite destination MUST be `${apiBase}/api/:path*` — if the `/api` prefix is dropped, every authenticated call 404s (the API mounts all routes under `/api/...`). This was a real bug; don't "simplify" it back.
- SSE chat protocol (`POST /api/chats/stream`): the server emits **named** events (`event: token|emotion|crisis|done|error`), and token chunks are named `token` events. The web client (`apps/web/src/lib/api.ts`) dispatches only named events and resets the event name after each `data:` line, so bare `data:` lines are silently dropped. Keep tokens named.
- Boot-time session refresh (`/auth/refresh`) must be called with `auth: false` in the web client: a 401 there is normal for logged-out visitors and must not trigger the redirect-to-/login unauthorized handler.
- Access-token expiry mid-session (15m TTL) must NOT surface as "Request failed (401)": `apps/web/src/lib/api.ts` now awaits the silent refresh (`onUnauthorized` handler returns the refresh promise) and retries the failed request once — both in `api()` and in `streamChat`. Keep the retry-once guard; the unauthorized handler also pushes to /login when refresh fails.
- Emotion lexicon lives in `apps/api/src/emotion.ts`. The spec's canonical example "I failed my interview..." used to score neutral (zero lexicon hits) — achievement/failure words ("failed", "rejected", "blew it") were added to the `frustrated` dimension. When adding emotion words, test with `detectEmotion`.
- Two canonical companions with ids `arpita` and `biniit` (`apps/api/src/data/personalities.ts`). `getPersonality` falls back to Arpita for unknown ids, so old DB rows (e.g. `gentle-therapist`) keep working.
- Node 22+ `node:sqlite` is used; the SQLite file is `apps/api/data/vichar.db` (WAL mode). `resetDb()` clears tables for tests.
- The local LLM engine (`apps/api/src/llm/local.ts`) is deterministic per (personality, emotion, message-hash) and offline — the default `LLM_PROVIDER=local`. OpenAI-compatible streaming (`LLM_PROVIDER=openai`) is a drop-in.
- Small talk is handled by a SHARED category detector in `emotion.ts`: `smallTalkCategory(text)` (categories: greeting, checkin, dontknow, status, thanks, bye, casual) and `isSmallTalk`. `local.ts` imports it to pick a short warm reply pool per category; `detectEmotion` forces small talk to `neutral` and skips history-continuity for it, so "hi"/"idk"/"ok" after an anxious message never inherit the emotion or get the clinical template. Extend the vocabulary in ONE place (the `SMALL_TALK_CATEGORIES` regexes + `SMALL_TALK_REPLIES` pools in local.ts) — keep both in sync.
- Situations (what the message is ABOUT, vs how the user feels) are also detected by a SHARED function in `emotion.ts`: `situationCategory(text)` → moodoff | overthinking | depression | breakup | patchup | relationship | exam | interview. `local.ts` composes the reply from per-situation, per-companion pools (`SITUATION_REPLIES` with openers/advice/questions) plus the usual mirroring + sign-off, and every reply carries emojis (`EMOTION_EXPRESSION` per emotion on the generic path). Order in `SITUATIONS` matters (depression/breakup/patchup before exam/interview/relationship). Gotcha: the breakup regex's `my ex` must be `\bmy ex\b` or it matches "my exam" and hijacks exam messages.
- The empathy framework (Steps 1-8) lives in `emotion.ts` as `detectPattern` (30 pattern: keys incl. black-and-white-thinking, self-blame, learned-helplessness, emotional-dependence, trust-issues, low-confidence, fear-of-abandonment), `detectIntent` (12 intent keys), `detectNeed` (18 need keys), `estimateIntensity` (5 levels: verylow/low/moderate/high/extreme; panic words or score >= 4 → extreme), and `detectHiddenEmotion` (hidden:* keys — "my friend ditched me" → hidden:rejection). All surfaced on `detectEmotion`'s `signals`. `local.ts` reads them: extreme/high negative → slower stream pace + validating slow-down prefix; venting/listen intent with negative valence (not extreme) → the "just listen or solutions together?" question; negative emotions → up to 2 gentle `PATTERN_ADDS` reframes; **hidden emotions with a neutral lexicon score → the reply opens with a `HIDDEN_ACKS` line instead of the generic greeting** ("my friend ditched me" must never get "I'm here, and I'm listening. What's been on your mind?"). Gotchas: (1) the negation dampener (`don't`) crushes lexicon scores, so gate the listen-question on `valence < 0`, not on `intensity`; (2) the neutral-lexicon entry `ok` matches inside "okay", so "it's fine, I'm okay" scores 0.8 (low), not verylow — use a no-lexicon message ("I went for a walk today") for verylow test cases. The full Steps 1-8 text (incl. hidden emotions, 5-level intensity, 6-step response structure, friend-like style rules) is embedded in `systemPrompt.ts` for the OpenAI provider.
- Emotion Validation Gate: `detectOutcome(text)` (in `emotion.ts`) tells whether something already HAPPENED — `positive` ("got the job", "I passed") vs `negative` ("failed", "didn't get") vs null. It is surfaced as `outcome:positive|negative` on the emotion signals. In `local.ts` the gate runs BEFORE the situation branch: positive → `CELEBRATION_REPLIES` pool (never the generic greeting, never condolence); negative + exam/interview situation → `NEGATIVE_OUTCOME_REPLIES` pool (acknowledge the loss, never congratulate, never pre-emptive "you'll do great" advice). Breakup/patchup etc. are NOT intercepted — their pools already match. Gotchas: (1) the positive regex must exclude "passed away"/"passed on" and "won't" ("i won" as a lexicon phrase matches inside "i won't" — removed from the lexicon); (2) fears ("what if I fail") are NOT outcomes — they must stay null; (3) "I'm not well"/"sick" is a new `unwell` situation (physical-vs-emotional question) — its regex must use `i'?m sick(?! of)` so "sick of everything" stays frustration. Celebration lexicon additions: "got the job", "got promoted", "aced", "cleared the exam", "passed my exam" etc. on the `joyful` dimension.

## Tooling quirks
- Runtime SQLite files live in `apps/api/data/`; `.gitignore` must use `/apps/api/data/` rather than the broad `data/`, because `apps/api/src/data` contains required TypeScript source.
- Do NOT run `npm install` at the repo root on this Windows setup (EPERM creating workspace symlinks) — always `npm --prefix apps/<app> install`.
